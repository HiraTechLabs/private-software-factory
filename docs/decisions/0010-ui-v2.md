## Context
The owner rejected the iteration-1 UI: grey, jargon (StateLight, LineRail, Gate, ModeTag,
"Shadowed", "Config errors"), invented sample data, and disabled gate buttons. A new design
mockup (`docs/ui/mockup.html`) shows the two key pages — Today (inbox-like) and Request
(pull-request-like with a sticky decision box).

## Decision
1. Rebuild the UI on the mockup: light paper page, deep teal accent, dark teal left rail,
   status colors amber (needs you), blue (working), green (done), red (failed), grey (not
   started); a status always carries its text label.
2. Tokens are rewritten from the mockup values (ink/ink-soft/paper/card/line/accent/need/
   need-bg/work/done/fail/fail-bg/idle; radius 8/12, rail 232px, base 17px); the old
   `shadow`, `run`, `hold`, `stop` tokens are removed; IBM Plex requirement and
   `docs/ui/fonts-todo.md` are deleted (system font stack, Arabic-capable fallback).
3. Vocabulary: Status, Pipeline, Decision box ("Your decision"); the banned column of 5.3
   never appears; provider words are "You paste" / "Local model" / "Demo model".
4. No dead controls (R10 planned features are never rendered, not even disabled).
5. Dark theme follows `prefers-color-scheme`; logical CSS properties only.

## Reasons
- Match the mental models the owner already has (inbox, pull request) instead of teaching new ones.
- Color is redundant with text; contrast tests stay in CI.

## Alternatives rejected
- Keep the 15-component catalog and rename it: polish on top of the wrong foundation.

## Consequences
- The `/ui` route, catalog template, and `tests/test_ui_catalog.py` are deleted; ui_lint rules
  change to dead-control and banned-word checks.
- Components grow only when a page uses them.
